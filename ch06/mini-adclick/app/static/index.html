광고 클릭 집계 실험실

휴대폰으로 광고를 누르고, 네트워크와 서버에 문제를 일으켜 보세요. 집계는 Apache Flink, 윈도는 10초(교재 1분을 축소), 시각은 UTC. 탭을 여러 개 열면 휴대폰이 여러 대가 됩니다.

실험 순서 (교재 3단계 주제별)
  1. 정상 — 광고 몇 번 누르기. 점이 윈도 안에 찍히고, 윈도가 닫히면 장부 = 집계 ✓
  2. 이벤트 시각 vs 처리 시각 (그림 12) — ✈ 비행기 모드 켜고 몇 번 누른 뒤 8초쯤 있다가 끄기. 점은 누른 시각에, 점선은 도착 시각으로 이어진다. 처리 시각 열은 엉뚱한 윈도에 센다
  3. 워터마크 (그림 13·14) — 워터마크 0초로 두고 2~3초짜리 비행기 모드 → 버려짐(✗). 5초로 올리고 다시 → 잡힘. 대신 윈도 결과가 늦게 나온다
  4. 아주 늦은 이벤트 → 재집계 검증 (그림 28) — 비행기 모드로 30초 넘게 → ✗, 장부보다 집계가 모자람 → 🔍 재집계 검증 → 보정
  5. 클라이언트 중복 — 📶 불안정한 네트워크 켜고 누르기. 응답이 사라져 폰이 재전송(↻) → 같은 click_id 가 두 번 와도 한 번만 센다
  6. 서버 장애 중복·유실 (그림 17~20) — 전략을 고르고 💥 장전 → 광고 누르기. 그 윈도 결과가 나온 직후 Flink TaskManager 가 죽는다. ① 유실(−), ② 중복(+), ③ 정확
  7. 스냅숏 = Flink 체크포인트 (그림 26·27) — ②에서 체크포인트 켜고/끄고 💥. 켜면 마지막 체크포인트 뒤만 다시 읽고, 끄면 배포 시점부터 다시 읽어 이미 낸 결과까지 또 낸다
  8. 버그 배포 → 재계산 (그림 11) — 🐞 배포(세이브포인트로 잡 교체) 후 몇 번 누르기 → 집계가 2배(+). 수정 배포 → 🔁 재계산(같은 SQL 의 유한 잡) → 닫힌 윈도가 원본으로 다시 집계된다. 과거를 몇 초 만에 몰아 읽으면 워터마크가 늦게 올라가서, 실시간에선 버려진 늦은 클릭까지 잡힐 수 있다 (재처리 결과 ≠ 실시간 결과)
📶 연결됨
✈ 비행기 모드클릭이 폰에 쌓였다가 다시 켜면 전송
📶 불안정한 네트워크응답이 사라지면 같은 클릭을 재전송

이벤트 시각 타임라인 점 = 클릭(누른 시각) · 점선 = 늦게 도착 · 세로 띠 = 10초 윈도 · 워터마크 = Flink 윈도 연산자의 실제 값

집계됨 + 그 칸이 장부보다 많이 집계됨 중복 도착 → 한 번만 ✗ 늦어서 버림 (광고 서버가 같은 규칙으로 표시) 아직 결과 없음 · ? 빠짐 굵은 테두리 = 내 폰

정답 장부 vs 집계 DB 장부 = 광고 서버가 받은 고유 클릭(이벤트 시각) · 집계 = ClickHouse sum(clicks)

윈도 (UTC)상태장부이벤트 시각 집계처리 시각 집계판정

상태: 열림 → 워터마크 대기(윈도 시각은 지났지만 늦은 클릭을 기다림) → 닫힘. 판정은 닫힌 윈도에서만.
